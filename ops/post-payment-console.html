Post-Payment Console

Use this immediately after Stripe confirms payment so the buyer moves into safe intake, private workspace setup, and scheduling without drift.

Safety Rule

Do not accept production credentials, active tokens, customer data, private source code, or final customer reports in public GitHub issues or ordinary email.

One-Command Handoff Review Launcher

Open the post-payment console, paid handoff builder, approval packet, runbook, automation guide, payment-to-delivery SOP, and delivery console together.

npm run delivery:open-handoff

Payment Confirmed Checklist

  1. Confirm package and customer email from Stripe.
  2. Save public-safe payment evidence outside the public repo.
  3. Verify the payment evidence.
  4. Approve the paid handoff packet.
  5. Run the one-pass handoff command from this repo with the verified payment evidence file and an output path outside the public repo.
  6. Review the generated draft-only intake start message.
  7. Approve the exact intake message before sending.
  8. Use a private handoff path before accepting sensitive materials.
  9. Use the generated private pipeline status as the paid delivery record.

Payment Evidence Gate

Run this before the one-pass handoff. The evidence file is created and verified outside the public repo.

npm run delivery:evidence -- --customer "{{customer_company}}" --package "{{package_name}}" --payment "{{stripe_payment_reference_or_receipt_url}}" --contact "{{technical_contact_email_or_secure_url}}" --safe-intake "/path/outside/public/repo/intake" --operator "{{initials}}"

One-Pass Handoff

Use after payment clears and exact handoff values are approved. This also writes a draft-only intake message in the private customer communications folder.

Build approval packet 
npm run delivery:handoff -- --file /path/to/approved-paid-audit-handoff.txt --payment-evidence /path/to/payment-confirmation-evidence.json

Safe Intake Paths

  1. Customer-owned private repo with time-limited read access.
  2. Customer-owned shared folder with time-limited access.
  3. Encrypted archive with password through a separate channel.
  4. Sanitized screenshots or config excerpts.
